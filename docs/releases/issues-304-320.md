## #317: same-data placement comparison

The root reviewer measured the same synthetic **ToDo 9 / Habit 2 / Project 2 / Focus 5** fixture, including a long Focus string, through the browser tool. Values below are document-coordinate top positions in CSS pixels; they are not task-completion times. The baseline is Today → learning → Focus. The accepted candidate is Today → Focus → learning. No horizontal overflow was observed in these measured comparisons.

| Viewport width | Baseline Focus / first ToDo | Focus-before-Today: Focus / first ToDo | Accepted after-Today: Focus / first ToDo |
| --- | --- | --- | --- |
| 320px | 1509 / 260 | 102 / 649 | 1223 / 260 |
| 390px | 1432 / 260 | 102 / 649 | 1207 / 260 |
| 1280px | 1024 / 322 | 164 / 487 | 872 / 322 |

Moving Focus before Today added **389px** before the first ToDo on phones and **165px** on desktop. The accepted candidate moved Focus earlier by **286px / 225px / 152px** while keeping the first ToDo at the same position. This supports the narrower layout choice without claiming that all content fits above the fold or that the user prefers it. Focus content/order, limits and touch/text sizes were not reduced to force a fit.

A separate stacked-right Today prototype did not produce a demonstrated height improvement in the measured fixture. The existing three-column desktop layout is therefore retained; this result does not establish that every possible alternative is worse. Habit-heavy/few-item, Focus-empty, loading/failure, dark/palette and actual action checks belong in the additional browser record. User preference remains unmeasured.
