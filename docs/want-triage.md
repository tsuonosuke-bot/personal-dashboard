# Wantsトリアージ運用

## 目的

Wantsを実装候補だけに限定せず、思いつき、予定、調査、執筆、習慣、言葉を受け止める未整理箱として扱います。整理時に正本を選び、元Wantには振り分け履歴を残して自動的に完了します。

## 正本

| 内容 | 正本 |
| --- | --- |
| タスク・予定・調査時間 | Google Calendar |
| ソフトウェア実装 | GitHub Issue |
| エッセイ候補 | `writing_topics` |
| 習慣の定義・実施記録 | `habits` / `habit_logs` |
| 再利用可能な学び | Knowledge DB |
| 継続して意識する言葉 | `focus_items` |
| その日の記録 | 既存Journal |
| 元の着想と振り分け履歴 | `wants` / `want_routes` |

## 操作

1. Wantを思いついた時は、AIを呼ばずにそのまま登録する。
2. 後でActive Wantの「整理する」を開く。
3. 「AIに整理案を聞く」を押すか、自分で扱いを選ぶ。AIへの送信はボタンを押した時だけ行う。
4. AIが確認質問を返した場合は回答を入力し、「回答をもとに再提案」を押す。回答しただけでは送信しない。
5. AI案を使う場合も、分類・振り分け先・タイトル・補足を編集する。
6. プレビューを確認して明示的に確定する。Google Calendarの場合は「Google Calendarに登録」と表示する。
7. 確定後、内部の管理先へ登録、Google Calendarへ予定作成、または未接続の外部先について計画保存する。
8. 振り分けの登録または計画保存に成功したら、元Wantを自動的に完了する。
9. 振り分け先への登録に失敗した場合だけ元WantをActiveのまま残し、同じ確認内容から再試行する。

### Focusの運用

1. Compassで対象Wantを「残す → Focus」に振り分け、言葉と補足を確認して確定する。
2. Personal Hubの先頭にActive Focusが指定順で表示される。
3. Hubの「管理」から文言・補足を編集し、上下で並び替える。
4. 今は表示しない項目は「表示から外す」にする。元Wantと振り分け履歴は削除しない。
5. Active Focusは5件まで。再表示または新規振り分け時に満杯なら、先に1件を表示から外す。

## AIを呼ぶタイミングと権限

```text
Wantを登録
  ↓（AIなし）
「整理する」
  ↓
「AIに整理案を聞く」 ── ここで初めてClaude APIへ送信
  ↓
分類・振り分け先・下書きの提案
  ↓
人が編集・プレビュー・確定
  ↓
振り分けアダプタが登録または計画保存
  ↓
元Wantを自動的に完了
```

- Want登録時、Compass表示時、定期実行ではAIを呼ばない。
- AIは提案専用で、Google Calendar、GitHub、Knowledge DB、Journal、Supabaseを操作できない。
- AIの出力は許可済みの分類・振り分け先だけを受け付け、サーバー側でも再検証する。
- AI案は未保存。ユーザーが既存の確認画面で確定するまで正本も履歴も変えない。
- 調査結果をKnowledgeやWritingへさらに育てる場合は、その結果を新しいWantとして登録し、別の明示操作でAIへ整理を依頼する。

## 現在の接続境界

| 振り分け先 | 現在の動作 |
| --- | --- |
| Writing | `writing_topics` へ登録し、対象IDを確認 |
| Habits | `habits` へ登録し、対象IDを確認 |
| Focus | `focus_items` へ登録し、対象IDを確認 |
| アーカイブ | 振り分け完了として履歴を保存 |
| Google Calendar | OAuth接続後、日付・時間を確認してメインカレンダーへ作成し、再取得したID・URLを保存 |
| GitHub | `planned` として保存。外部送信なし |
| Knowledge DB | `planned` として保存。重複・カテゴリ検証前には登録しない |
| Journal | `planned` として保存。既存Journalの書込仕様確定前には登録しない |

Google Calendarは `calendar.events` scopeだけを要求し、`primary` カレンダーへ `Asia/Tokyo` で一方向に新規作成します。日付のみなら終日、日時なしなら登録を拒否します。更新トークンはサーバーで暗号化し、Claudeとブラウザには渡しません。GitHub・Knowledge DB・Journalは、認証方法、下書き内容、重複防止、作成後の再取得方法を個別に合意してから有効化します。

## 失敗時

- 振り分け先への登録に失敗した場合は、元Wantの内容や状態を変更しない。
- 内部登録またはGoogle Calendar登録に失敗した振り分けは `failed` として記録する。
- 同じ処理IDを再送しても、作成済みの対象を重複登録しない。
- 振り分け成功後に元Wantの完了だけ失敗した場合、同じ処理IDで完了処理だけを再試行する。
- Wantが別画面で変更されていた場合は409で拒否し、再読込を求める。
